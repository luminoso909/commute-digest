# 通勤日报 · 需求、计划与验收对应表

## 一、需求说明（SPEC）

学生和上班族通勤时，希望几分钟内了解半天内值得关注的事，也能顺着原文核实报道。读者选好关注领域、关键词、中英文和投递时间后，可以在邮件里扫读摘要，在网页上看完整报道和分析。

| 项目 | 约定 |
| --- | --- |
| 输入 | 账号的关注领域、关键词、版式、语言、邮箱和模型设置，以及本期的起止时间。 |
| 处理 | DeepSeek 检索候选新闻，Python 核对原文发布时间、筛选选题并去重。所选模型根据原文摘录或有出处的笔记生成双语稿，Python 校验后存入 SQLite。 |
| 输出 | 每期主版 3–6 条。个人邮件含事实摘要、来源及本期链接。网页显示报道细节与分析。Mac 小组件显示最近一次个人投递的标题，可打开同一期。 |
| 范围 | 以北京时间 05:00 和 17:00 划分最近 12 小时。上一期截止点归上一期，本期截止点归本期。来源不足时停止本次出刊。模型对影响的分析，由读者结合原文判断。 |

## 二、实现计划（PLAN）

| 顺序 | 实现工作 | 阶段验证 |
| --- | --- | --- |
| 1 | 定义一期日报的时间窗、来源、双语字段，并区分固定日报编号与个人期数。 | 用跨午夜、恰在截止点和两个同名账号的样本检验规则。 |
| 2 | 接入联网检索和模型编稿，将核实过的报道写入 SQLite。 | 用过期新闻、同事件重复报道、字段缺失和不足三条的草稿验证筛选。 |
| 3 | 接入网页、邮件和小组件，让几个入口指向同一份归档。 | 核对网页正文、邮件摘要和链接中的日报编号，检查他人账号无法读取。 |
| 4 | 在 AutoDL 配置公网、模型、SMTP 和早晚调度，进行联调。 | 检查服务与下一触发时间，用三个关注领域不同的账号试投并核对收件、回链。 |

| 需求及可判断的标准 | 实现位置 | 验证方法与结论 |
| --- | --- | --- |
